AUREON — GOOGLE DRIVE OAUTH SETUP & SECURITY GUIDE
===================================================

STATUS
------
Google Drive OAuth and Drive API calls are NOT implemented in the current app
build. This guide records the approved zero-server-access design. Do not treat
these instructions as proof that Connect Google Drive already works.

SECURITY DECISION — GOOGLE DRIVE DATA MUST STAY ON THE DEVICE
-------------------------------------------------------------
For the public multi-user release, Google Drive access must be performed by
the native AUREON client on the user's device.

The following Google-derived material MUST NOT be sent to AUREON's central
backend, a user's Cloudflare Worker/D1 database, analytics, crash reporting,
or any other third-party server:
- Google OAuth authorization codes, access tokens or refresh tokens.
- Drive file contents, file names, file IDs, MIME types, parents, timestamps,
  permissions, thumbnails, change tokens, or other Drive metadata.
- AUREON indexes, folder maps, or sync records derived from Drive contents.

The Cloudflare Worker may continue to handle AUREON Master Account/backend
functions, but it must not proxy Google Drive API calls, exchange Google auth
codes, refresh Google tokens, or receive Google Drive data. Do not put Google
credentials or Drive-derived metadata in the existing encrypted provider
vault. Client-side encryption does not make sending restricted Drive data to
a third-party server an approved exception.

WHY THIS DESIGN
---------------
Google classifies https://www.googleapis.com/auth/drive and
https://www.googleapis.com/auth/drive.readonly as Restricted scopes. Public
apps requesting them still need Google's applicable OAuth verification.
Google's security-assessment requirement applies when the app stores/transmits
restricted data on servers or can access that data from/through a third-party
server. Keeping all Drive operations and Drive-derived data on-device is
intended to avoid that server-side assessment trigger; it does NOT remove
Restricted Scope verification or guarantee Google's approval.

PLATFORM FLOWS
--------------
Android:
- Use Google's Android AuthorizationClient / supported Android authorization
  APIs to request Drive authorization on-device.
- Request the minimum runtime scope needed for the user's action. For AUREON's
  full existing-Drive management requirement, the intended scope is:
  https://www.googleapis.com/auth/drive
- Obtain short-lived access tokens on-device and call Drive API directly.
- Re-run AuthorizationClient.authorize() when needed; Google documents that
  previously granted permissions can be reused without prompting while the
  grant remains valid. Do not request offline server access or send an auth
  code to a backend.
- Do not persist Google refresh tokens. Keep access tokens in memory and use
  the Google authorization client token cache/reauthorization behavior.
- Associate the Android OAuth client with the exact package name and release
  signing SHA-1 fingerprint.

Windows (later platform):
- Use the native Desktop app OAuth client and Google's installed-app flow with
  the external system browser and PKCE.
- Exchange the authorization code in the Windows client, never in a Worker.
- Store any locally required credential material only in Windows-protected
  local credential storage. Never sync it to AUREON's backend.
- Confirm the current Google desktop-client policy and token lifecycle before
  implementation; do not reuse a Web client secret in a desktop app.

SCOPES AND USER REQUIREMENTS
----------------------------
- The user's requirement is to list and manage all existing Drive files, not
  only files individually opened with AUREON.
- drive.file is non-sensitive but is limited to files created/opened/shared
  with the app; it does NOT satisfy full-library access on its own.
- drive.readonly provides full-library read/download but cannot upload, edit,
  move, rename or delete.
- drive provides full-library read/write/manage access and is the intended
  scope if all requested AUREON file-management actions remain in scope.
- Do not request both drive and drive.readonly; drive already covers the
  read/write operations. Do not request broader scopes for unrelated features.

DATA AND CROSS-DEVICE BEHAVIOR
------------------------------
- Drive file content and Drive-derived metadata/indexes remain local to each
  device.
- AUREON Master Account sign-in does not silently transfer Google authorization
  between devices. Each device obtains its own local Google authorization.
- Do not promise automatic restoration of Google tokens on a new device.
- A portable AUREON metadata backup may be exported/imported as a user-
  controlled encrypted file. It must not be uploaded to the AUREON Worker.
  Any future cloud sync of Drive-derived metadata requires a separate policy
  review before implementation.
- Google Drive originals must never be deleted automatically after upload.

OWNER SETUP
-----------
1. Keep the AUREON Google Cloud project: aureon-7f612.
2. Keep Google Drive API enabled.
3. Keep OAuth app type External for a public consumer app.
4. Keep the public homepage, privacy policy, terms, and authorized domain
   accurate and accessible.
5. In Data Access, declare only the scope actually used by the released build.
   The intended full-access scope is https://www.googleapis.com/auth/drive.
6. Android OAuth client: exact application ID plus the release signing SHA-1.
7. Windows OAuth client: Desktop app type, created when Windows integration
   is ready.
8. Do not submit the app for verification until the real native OAuth flow,
   Drive operations, disconnect/revoke behavior, and privacy disclosures are
   implemented and demonstrable.

RELEASE GATES — DO NOT SKIP
---------------------------
- Confirm Google accepts AUREON as a permitted Drive application type. The
  product's backup/sync and file-management features must be demonstrated.
- Complete the Restricted Scope verification for a public app.
- Confirm with Google whether the final client-only implementation is outside
  the annual third-party security-assessment requirement. Never assume this
  exemption solely from architecture notes.
- Provide a demo video showing user consent, full-Drive file listing and the
  actual on-device data flow.
- Update the Privacy Policy to describe the shipped behavior precisely and
  satisfy Google's Limited Use requirements.
- Test authorization denial, cancellation, revoked access, token expiry,
  offline mode, multiple Google accounts, and device migration.
