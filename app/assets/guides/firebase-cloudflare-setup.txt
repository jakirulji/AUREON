AUREON — FIREBASE & CLOUDFLARE SETUP GUIDE
=============================================

This guide stays inside the AUREON app. You create and own both services.
AUREON does not use a shared developer backend. Never share passwords,
service-account JSON, private keys, Cloudflare API tokens, or Worker secrets.

PART 1 — CREATE YOUR FIREBASE PROJECT
-------------------------------------
1. Open https://console.firebase.google.com/ and sign in with your Google account.
2. Select "Add project".
3. Enter a project name, for example "AUREON Personal".
4. Follow the project creation steps. Google Analytics is optional for AUREON.
5. Open the new project overview.
6. Select the Web app icon (</>) to register a web app.
7. Give it a nickname such as "AUREON Client". You do not need Firebase Hosting.
8. Finish registration and open the Firebase configuration snippet.
9. Copy only:
   - apiKey          -> Firebase Web API key
   - projectId       -> Firebase project ID
10. Keep this browser tab open while enabling Authentication.

PART 2 — ENABLE FIREBASE SIGN-IN
--------------------------------
1. In Firebase Console, open Build > Authentication.
2. Select Get started if prompted.
3. Open Sign-in method / Providers.
4. Enable Email/Password.
5. Also enable Email link (passwordless sign-in) if it is offered as a
   separate provider option. Save the changes.
6. Open Authentication > Settings > Authorized domains.
7. Confirm the domain used by your AUREON email-link flow is authorized.
   Add only domains you actually use; do not add arbitrary domains.
8. Return to AUREON > Account. Enter the Web API key and Project ID.
9. Give the profile a memorable name, such as "Personal Firebase + Cloudflare".
   Do not paste a service-account JSON file or private key into AUREON.

PART 3 — CREATE A CLOUDFLARE ACCOUNT
------------------------------------
1. Open https://dash.cloudflare.com/ and create/sign in to your account.
2. Complete the account verification steps.
3. Open the Cloudflare dashboard. You do not need to buy a domain merely
   to create a Worker and D1 database for this setup.

PART 4 — CREATE THE D1 DATABASE
--------------------------------
1. In Cloudflare dashboard, open Workers & Pages.
2. Open Storage & databases (or Storage) > D1 SQL Database.
3. Select Create database.
4. Give it a unique name, for example "aureon-vault-db".
5. Create the database and open its details page.
6. Record the database name and database ID for the Worker configuration.
7. A database existing by itself is NOT enough: the Worker must be bound to it.
8. Apply the AUREON schema/migrations supplied with the matching Worker source
   in this repository. Do not invent table names or paste an unrelated schema.
   If the repository's Worker package supplies migration files, run those
   migrations against this D1 database before using vault operations.

PART 5 — CREATE AND DEPLOY THE AUREON WORKER
--------------------------------------------
1. Open Workers & Pages > Overview.
2. Select Create application > Create Worker.
3. Choose a name such as "aureon-personal-api" and deploy the starter Worker.
4. Open the Worker and note its HTTPS workers.dev URL, for example:
   https://aureon-personal-api.<your-subdomain>.workers.dev
5. Open the Worker settings > Bindings.
6. Add a D1 database binding and select the D1 database created in Part 4.
7. The binding variable name MUST match the name expected by the AUREON
   Worker source/configuration in this repository. Do not guess this name.
8. Add any required Worker environment variables and secrets exactly as
   documented by that Worker source. Keep secrets in Cloudflare Worker
   Secrets; never put them in AUREON's Firebase fields or source code.
9. Deploy the actual AUREON Worker implementation from this repository,
   not the Cloudflare starter "Hello World" Worker. The starter Worker is
   only a way to create the Worker resource.
10. After deployment, open the Worker URL and verify its documented health
    or status endpoint, if the Worker source defines one.

IMPORTANT ABOUT THE WORKER SOURCE
---------------------------------
A Worker URL alone does not create the AUREON API. The deployed code, D1
binding name, database schema/migrations, and required environment settings
must match one another. Follow the Worker package's own README and migration
instructions in this repository. If those files are absent or unclear, stop
before using vault/recovery features rather than guessing configuration.

PART 6 — SAVE THE BACKEND PROFILE IN AUREON
-------------------------------------------
1. Open AUREON > Account.
2. Tap "Read Firebase & Cloudflare setup guide" whenever you need these steps.
3. Enter:
   - Profile name: a name you recognize
   - Firebase Web API key: the apiKey from your Firebase Web app config
   - Firebase project ID: the projectId from Firebase
   - Cloudflare Worker HTTPS URL: the deployed AUREON Worker URL
4. Tap "Save & use this backend".
5. Create or sign in to your AUREON Master Account.
6. Verify your email before using protected cloud-vault/recovery operations.
7. The saved profile is stored locally and bound to the signed-in Firebase
   identity by AUREON. Do not use the same profile with a different identity.

SECURITY CHECKLIST
------------------
- Never share Firebase account passwords, Cloudflare login passwords,
  API tokens, service-account JSON, private keys, or Worker secrets.
- Firebase Web API key and project ID are client configuration values,
  not substitutes for server-side security rules.
- Keep Worker authentication and D1 authorization checks enabled.
- Use HTTPS Worker URLs only.
- Keep an independent backup of recovery keys and metadata.
- Creating Firebase/Cloudflare resources does not mean AUREON cloud sync,
  provider login, or file transfers are automatically configured.
